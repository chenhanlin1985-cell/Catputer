# Catputer 排障记录（BLE 输入 + 触屏交互黑屏）

本文记录两类已经复现并修复的问题，方便后续快速定位。

## 1) BLE 键盘输入卡顿（Cardputer）

### 现象
- BLE 已连接，但输入几个字符后明显延迟。
- 连续输入会卡住，偶发重复字符（如连续 `aaaa...`）。
- 看起来像“无响应”，但设备不一定重启。

### 根因
- BLE 模式下仍有部分网络/同步逻辑并行运行，造成时序干扰。
- 高频按键上报在队列压力大时放大阻塞。
- 队列满载时，按下/抬起事件处理不对称会导致重复输入感。

### 已修复
- 进入 BLE 模式时清理语音相关状态，减少跨模式残留。
- BLE 模式下暂停非必要循环任务（如部分网络广播/同步逻辑）。
- 调整输入上报策略与队列参数，降低抖动和拥塞。

### 回归检查
- 连接 BLE 后连续输入短句、长句、快速重复按键。
- 观察是否仍有明显延迟、冻结、重复字符。
- 断开重连后重复测试，确认会话切换稳定。

## 2) 触屏端交互后黑屏闪回（Waveshare AMOLED）

### 现象
- 点击“清理/喂食/玩耍”等交互后，企鹅走到家具附近。
- 显示“清理完成”等文案后出现黑屏闪烁或状态异常回位。
- 一度出现“反复自动清理”的异常（调试开关引入）。

### 根因（已确认）
- 交互动作完成后会触发临时状态文案。
- 临时状态文案被自动入队到本地 TTS。
- 在低堆内存场景下，本地 TTS 合成调用阻塞主循环，导致黑屏/假回位体验。

### 已修复
- 关闭触屏端 `setTemporaryStatus` 的自动语音入队（仅触屏端，其他端不受影响）。
- 关闭并移除“自动触发清理动作”的临时调试开关。
- 清理本轮排障埋点日志（`[ROOM]/[ACT]/[STATE]/[MSG]/[BOOT]`）避免噪音。

### 回归检查
- 触屏端依次点击：清理 -> 喂食 -> 玩耍。
- 期望：不再自动循环清理，不再黑屏闪回，动作与数值变化正常。

---

### 刷机必看

1. `COM8` 触发 1200bps touch，系统出现断开/重连提示音。
2. 脚本高频轮询端口，日志出现 `probe ... COM9`。
3. 立即进入：`[COM9-WAIT] COM9 detected. Starting esptool flash...`
4. 写入 + 校验通过：`Hash of data verified.`
5. 复位完成：`Hard resetting via RTS pin...` 与 `[COM9-WAIT] Flash completed on COM9.`

若卡住，先看是否缺少第 2 步（`COM9` 从未出现）；没有第 2 步时不要继续刷写阶段排查。

## 3) 触屏端联网/天气反复失效（Waveshare AMOLED）

### 现象
- 配置正确，最小诊断固件可以启动 WiFi。
- 主固件里天气长期显示离线或未知。
- 串口显示 `WiFi.mode(WIFI_STA)` 失败，模式仍为 `0`，状态可能停在 `254`。

### 根因（已确认）
- 不是 WiFi 密码、城市、天气 API 或 HTTP 层问题。
- 触屏主固件在 LVGL 初始化时给双缓冲分配了接近全屏级别的 DMA 内存。
- WiFi 驱动需要内部 RAM，后续按需联网时内部堆只剩一万多字节，导致 WiFi 模式切换失败。

### 已修复
- 将 LVGL 绘图缓冲改成 32 行分块刷新，减少内部 DMA 内存占用。
- 保留主固件按需联网流程，不再恢复开机强制联网。
- `COM9` 写入成功后不再把 `COM8` 日志空窗当成联网根因追查。

### 回归检查
- 设备主界面能正常显示。
- 天气能联网刷新；断网时显示缓存或离线状态。
- 串口可看到 `[WEATHER] WiFi mode: ok=1 mode=1 ...` 或后续连接成功日志。

## 4) 触摸触发联网后重启（已收敛）

### 现象
- 点击宠物触发联网/互动后，设备立刻断开串口并重启。
- 多次表现为“看起来像网络崩溃”，但并不稳定复现到天气请求点。

### 根因（串口证据）
- 关键日志序列：
  - `[TOUCH_AI] skipped low memory ...`
  - `[LOCAL_TTS] Begin synth ...`
  - 随后串口断开并重启
- 说明重启触发点在 **本地 TTS 合成路径**，不是天气拉取频率本身。

### 已处理（当前稳定方案）
- 触屏端临时禁用 TTS 链路（本地/代理都不走）。
- 清理待播语音，避免触摸互动隐式进入语音合成。
- 触摸互动保留文字气泡，不自动语音播报。
- 设备实测：触摸触发联网后**不再崩溃重启**。

### 约束（后续开发必须遵守）
- 触屏端在 TTS 分区/内存方案重构前，默认保持 `TTS disabled`。
- 任何新增互动功能，不得依赖 `companion.speak()` 作为默认路径。
- 若后续要恢复 TTS，必须先完成：
  1. 分区与资源布局评估
  2. 串口压力回归（连续触发）
  3. 崩溃回溯验证（无 panic/backtrace）
