# 功能交付清单（固定流程）

目的：避免“功能做了但文档没更新、后续又反复踩坑”。

## 每次功能完成后，必须一起完成

1. 代码层收口  
- 只改本次功能相关模块，不顺手改稳定链路。  
- 本地至少完成一次目标环境编译（如 `waveshare-amoled-18`）。

2. 设备侧验证点  
- 记录“用户可见结果”而不是只记录代码点。  
- 记录至少一个失败回退路径（例如离线回退文案）。

3. 文档同步（同一提交）
- 在对应模块文档补“本次新增/变更/验收口径”。  
- 写清“依赖条件”（网络、SD、端口、按键方式）。  
- 写清“不改动项”（本轮刻意不动的稳定链路）。

4. 回归关注项
- 联网链路（WiFi、API Host/Port/Token）。  
- 触摸/按键交互是否被新任务阻塞。  
- 内存风险点（DMA/PSRAM/大 buffer）。

## 本轮已完成记录（2026-04-13）

功能：触屏主页“触摸宠物触发气泡对话（在线 AI 优先，离线回退）”。

- 触摸宠物后：联网且配置可用时，异步请求 AI，返回 2-3 句短对话气泡。  
- 离线或失败时：使用本地回退短句，保证陪伴反馈不中断。  
- 增加了节流与超时：避免连续触摸造成请求堆积和界面阻塞。  
- 编译验证：`pio run -e waveshare-amoled-18` 通过。
