# Catputer 跨机器重启与多端连接说明

这份文档用于你在“换电脑 / 新环境 / 新触摸端”时快速恢复开发与联调。

## 1. 当前项目状态（截至现在）

- 固件端：主设备为 `Cardputer / Cardputer Adv`，已包含宠物、聊天、语音、本地 TTS、蓝牙键盘模式等能力。
- 桌面端：`desktop/CatputerGodot` 已可做猫仓管理、进城/回端同步。
- 多端准备：已加入设备身份与能力字段（`device_id/device_type/caps`）和猫咪派遣字段（`assigned_device_id/runtime_location`），为触摸端接入做了协议预留。
- 触摸端：尚未刷入新触摸设备，当前是“代码准备完成，待设备联调”状态。

## 2. 换机器后的最小启动流程

1. 安装基础工具  
- Git  
- Python 3.10+  
- PlatformIO（CLI 或 VSCode 插件）  
- Godot 4.x（桌面猫舍）  
- `ffmpeg`（语音链路）

2. 拉取仓库并进入目录  
```powershell
git clone https://github.com/chenhanlin1985-cell/Catputer.git
cd Catputer
```

3. 准备本地环境变量（不要把真实密钥提交到仓库）  
- 参考：`.env.example`、`clawputer.local.ps1.example`
- 至少需要：
  - `WIFI_SSID`
  - `WIFI_PASS`
  - `API_KEY`
  - `API_HOST`
  - `API_PORT`
  - `STT_PROXY_HOST`
  - `STT_PROXY_PORT`

4. 启动本地语音代理（如果要语音）  
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\start-stt-proxy.ps1
```

5. 启动桌面端（Godot）  
- 打开 `desktop/CatputerGodot/project.godot`
- 进入“联动”页，开始监听设备广播

## 3. 联动与协议关键点（新机器必看）

### 3.1 端口

- UDP 广播状态：`19820`
- TCP 命令：`19821`
- UDP 文本推送：`19822`

### 3.2 设备识别字段

端侧状态包里现在有：
- `did`：设备 ID
- `dt`：设备类型（如 `cardputer`）
- `tc/kc/mc/sp`：触摸/键盘/麦克风/扬声器能力位

### 3.3 同步流程

1. 端侧先“进城”  
2. 桌面点“进城同步”拉取快照  
3. 在猫仓选择回端对象  
4. 点“出城回家”把选中猫同步回端侧  

备注：快照里已预留 `route.target_device_id`，后续触摸端接入可直接复用，不用再改字段。

## 4. 触摸端接入时的建议顺序

1. 先保证触摸端能发同结构广播（至少 `did/dt/caps`）  
2. 再接 `sync_enter/sync_ping/sync_leave`  
3. 最后做触摸交互 UI（先 MVP：主页+互动+聊天入口）

## 5. 常见问题与排障

### 5.1 蓝牙键盘输入卡顿

参考文档：`docs/ble-keyboard-troubleshooting.md`  
重点看串口 `BLEDBG` 指标（队列、丢弃、堆内存）。

### 5.2 聊天连接失败

先查 3 件事：
- 端侧网络是否在线
- `API_HOST/API_PORT/API_KEY` 是否正确
- 本地语音代理是否误当成大模型网关（两者是不同链路）

### 5.3 中文显示异常

- 优先确认编码与字体，不要在不同工具里混用错误编码保存。

## 6. 安全与提交规范

- 严禁提交真实：
  - Wi-Fi 密码
  - API Key
  - 私人网络地址映射
- 提交前检查：
```powershell
git status
git diff -- . ':(exclude).env*'
```
